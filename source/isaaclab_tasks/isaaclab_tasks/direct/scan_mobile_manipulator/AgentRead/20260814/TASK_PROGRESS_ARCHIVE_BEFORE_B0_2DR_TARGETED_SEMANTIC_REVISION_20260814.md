## B0-1A / B0-1B / B0-2D outcome and deferred evidence

The immediate schema-manifest blocker is resolved. H1--H4 now use an
independent tensor oracle, exact 19-name inventory, resolver-discriminating
Contract-C fixture, and widened isolated clean-child boundary. This is enough
to close the declared Phase-A pure/static/manifest gate, but not any runtime
gate.

B0 design recommends an event-profile-only coordinator invoked inside the
environment `_get_dones()` boundary after physical detection and before
autoreset. It separates the unique facts producer, lifecycle authority/state
store/ledger, terminal critic sidecar, and immutable handoff. Wrapper post-step
reconstruction and the current Contract-C resolver are explicitly rejected as
B0 authorities. Event global readiness remains fail-closed and the foundation
would remain dormant until later approved runtime gates.

B0-1A implements only the dormant `EnvironmentExecutionFactsProducer`, its
explicit raw-tensor input, canonical frozen factory/stamp construction, raw
prospective coverage projection, and per-env process-lifetime non-RNG token
allocation. Caller-provided episode/transition generations are preserved
exactly. The sole public producer capability is `build_facts()`.

B0-1B adds only the dormant `LifecycleGenerationClock` and its unversioned
runtime-private context/snapshot records. The clock owns episode generation
advance and contiguous transition candidate/explicit commit for one opaque
vector-environment domain. Candidate request never commits; an outstanding
candidate blocks another same-row request and episode advance; failed facts
construction can burn a token while the same candidate remains retryable.
Every vector mutation validates the full batch before one immutable state
replacement. The clock and producer retain separate locks/state and reference
neither other's mutation path.

Process lifetime means the owning environment domain retains one clock
instance for its whole lifetime. Numeric row IDs are domain-local, so another
clock with the same numbers is a distinct domain and cannot commit the first
clock's context. Arbitrary clock reconstruction is not a continuation and no
reconstruction/restore claim or API is made in B0-1B.

B0-2D closes the remaining lifecycle-mutation semantics at design level only.
Completion masks release for legal C+R/C+U combinations; same-pair C+F and
same-robot U+Rc fail before consume; F/R/U release causes deduplicate. Robot
state is projected from updated health, event-updated a0 ownership, and
structurally eligible unowned AVAILABLE work. This makes healthy robots
WAITING on ALL_TASKS_COMPLETED/NO_FEASIBLE_TASKS_REMAIN while preserving owned
EXECUTING work at TIME_LIMIT. B0-2D also freezes the exact event enum/tie-break
order, termination priority, receipt-independent prevalidation, one consume,
one finalization, and success-only non-observable store/clock publication.

The addendum does not claim CLAIMED->NAVIGATING->ALIGNING progression because
the frozen facts have no such raw edges. Existing active states are preserved,
and owner-gated completion/release can close them. This deferred progression
does not block the B0-2 lifecycle authority scope and does not authorize a
Phase-A contract change.

Still deferred: environment pre-reset hook and real raw-input capture;
lifecycle authority/state mutation/ledger/result; exact runtime completion
attribution; structural failure/health reporters;
terminal-sidecar HARL transport; expected-time estimators; retry/local-set/

The largest technical risk remains Phase C runner/trainer integration: a
